CALLBACK GUIDANCE

Finish sign-in safely.

The embed starts an authorization request; this checklist describes what a real callback must do.

  1. Require the callback to match the exact registered redirect URI.
  2. Read the stored transaction from the same browser session and compare the returned state before doing anything else.
  3. Reject errors, missing/expired transaction values, and repeated callback codes.
  4. Exchange the authorization code with the original PKCE verifier. Prefer a server-side exchange; do not put client secrets in browser code.
  5. Validate tokens, issuer, audience, expiry, and nonce against the actual provider's published metadata/JWKS before establishing a session.
  6. Clear transaction values and never place access or refresh tokens in URLs, logs, or localStorage.
Not implemented here: the included Worker returns 503, and this repository does not have an active token endpoint, ID-token signer, or JWKS.
