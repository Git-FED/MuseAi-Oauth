FOR SITE BUILDERS

Add a MuseAI sign-in button.

This is a copyable client-side starting point for OAuth authorization code + PKCE S256. It is not a live sign-in integration: the Worker in this repository returns 503, and the issuer/client values below are placeholders.

Not connected: Replace `https://login.example.com` and `YOUR_CLIENT_ID` with a deployed MuseAI issuer and registered client. The callback must be registered as an exact redirect URI. The authorization server and signed Muse approval hook are not implemented here.

BUTTON PREVIEW

The button below opens an honest local status page; it does not pretend to authenticate.

Sign in with MuseAI ↗
HTML + module import
<button id="museai-sign-in" type="button">Sign in with MuseAI</button>

<script type="module">
  import { startMuseLogin } from "/assets/museai-login.js";

  document.querySelector("#museai-sign-in").addEventListener("click", () => {
    startMuseLogin({
      issuer: "https://login.example.com",
      clientId: "YOUR_CLIENT_ID",
      redirectUri: new URL("/auth/callback.html", location.origin).href,
      scope: "openid profile"
    }).catch((error) => {
      console.error("MuseAI sign-in could not start:", error);
    });
  });
</script>

What the example does

It generates a random state, nonce, and PKCE verifier; computes the S256 challenge; stores the transaction values in session storage; and redirects to `/oauth/authorize`. A production callback must compare state and exchange the code securely. Do not put client secrets in browser code or claim a user is signed in until the server verifies the response.

Current limitation: this repository has no functioning OAuth authorization endpoint, ID-token/JWKS support, or Muse-agent approval verifier. The example is for integration planning and will fail against the included Worker.
